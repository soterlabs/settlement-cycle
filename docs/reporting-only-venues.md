# Venue reporting and MSC settlement

Every venue in a prime's YAML declares `settlement_enabled: true|false`.
All active venues are reported. Only venues with this flag enabled contribute
income or SDE value to MSC, receive cost-of-funds attribution, or enter the
settlement venue NAV. `skip: true` still means do not calculate a venue.
The former `display_only: true` YAML spelling is accepted as the inverse for
compatibility; conflicting flags and non-boolean values are rejected.

Grove's former display-only positions now run the existing valuation and
capital-flow accounting, reporting revenue without adding it to MSC. EOA
relay claims remain principal claims: yield is measured once at the paired
anchor, rather than also treating a principal return as EOA income.
Spark Savings V2 products retain their existing position-only treatment:
retail deposits and depositor VSR liabilities are outside the ALM settlement
boundary. They now explicitly have `settlement_enabled: false`. Robinhood
is included in Spark's block pins so the configured spUSDG position (S63)
is actually valued. Its `start_date: 2026-06-19` prevents historical runs
from resolving a reporting-chain pin before the product existed.

## API and artifact contract

`GET /v1/venues/{prime}` returns the **current** venue inventory with
`settlement_enabled`, `skip`, chain and pricing category. This endpoint reads
configuration only; it performs no provider requests. It does not reinterpret
historical snapshots using today's flags.

Fresh daily result snapshots and provenance (schema 1.1) contain:

- `venue_breakdown`: settlement venues, each with `settlement_enabled: true`.
- `reporting_only_breakdown`: reporting venues, each with
  `settlement_enabled: false`, position values, capital flows and revenue.
- Incentive rows additionally expose `incentive_accrual`, including daily
  eligible balances, applied rates, receipts, period income, cumulative
  accrual/receipts and the accrued or prepaid balance at cutoff.

The Markdown report and workbook call the separate section **Reporting-only
holdings** and show revenue and reward receipts. Its amounts are excluded
from the MSC headline. Provenance also exposes `results.reporting_only_revenue`
as an informational sum. Do not sum an issuer receivable with its underlying
position to calculate eligible capital.

Historical snapshots remain immutable. An exact legacy decoder maps the old
`display_only_breakdown` name and supplies the two newly introduced venue
metadata fields when replaying known historical schemas. Hash verification
uses the original payload. Publishing/finalizing still requires matching
code, configuration and input revisions. Historical artifacts using the old
name remain renderable; published settlements are not regenerated by this PR.

## Spark issuer incentives

S67 (RLUSD) and S68 (PYUSD) are separate reporting-only **receivables**, pricing
category `I`. Existing cash settlement recognition remains on its operating
venue. Accruing the receivable therefore does not book the same reward twice
in MSC. No assumed reward rate is applied to the USDS leg of an LP.

All eligible balances use UTC end-of-day state and ACT/365:

- RLUSD earns 4.5% APR on the Ethereum ALM's raw holding, its unborrowed
  SparkLend supply, and its RLUSD amounts in open RLUSD/USDS Uniswap v4 NFTs.
  The Morpho vault `0xFC8C624B6080a0a780583799f2A862DE936F6E22` earns only
  `max(0.045 - net_vault_APR, 0)` on the ALM's position.
- PYUSD uses daily official FRED **DFEDTARL** (fractional units), subtracts
  0.00625, and adds 0.02575 before **2026-03-09**, then 0.018. This is an APY;
  the applied APR is `365 * ((1 + APY) ** (1/365) - 1)`. Eligibility covers raw
  ALM PYUSD, unborrowed SparkLend supply, open PYUSD/USDS v4 positions, and
  Spark's proportional PYUSD reserves in Curve S25 through **2026-06-30**
  inclusive. Missing daily FRED observations fail the calculation.
- Lending eligibility is supplied balance times
  `idle_underlying / (idle_underlying + stable_debt + variable_debt)`.
  Principal already borrowed by other users earns no issuer incentive.
- v4 NFT ownership is reconstructed from Transfer history through the cutoff;
  the configured PoolKey is checked against the supplied pool ID. Minted,
  transferred, closed, and out-of-range positions are handled by the existing
  position decoder. The eligible balance is its token leg at cutoff, not
  half of LP value or a time-weighted intraday average.
- Morpho's configured `daily_share_return` convention derives net APR from
  consecutive day-end `previewRedeem` quotes for a fixed share amount, times
  365. `previewRedeem` accounts for pending fee dilution; the performance fee
  is not deducted again. This is **realized daily net APR**, not a quoted
  instantaneous lending APR. Confirm this interpretation before merging if
  the agreement requires the latter.

The cumulative balance is `opening_balance + sum(daily_accrual) - sum(receipts)`.
Negative balances are retained as prepayments. Configuration reconstructs
RLUSD/PYUSD from Spark's inception, **2024-11-18**, with zero opening claim,
rather than assuming an unknown January 2026 opening balance. This applies
the supplied agreement throughout that history; confirm a later agreement
start or provide a dated opening claim if those terms did not apply then.
The first backfill can require substantial archive reads; pinned extraction
inputs are cached for subsequent daily calculations.

Receipts match the supplied token, payer and recipient (the Ethereum ALM),
not arbitrary incoming transfers. RLUSD payer:
`0xb70e0fad7d0cf4c187365a84e728802ab24ca78b`; PYUSD payer:
`0xfc0539d019482d311c161ae3b756cdccdec45e87`.

USDG's engine uses receipts as accrual, per the 8-hour payment agreement;
its accrued balance is therefore zero with a zero opening balance. **S69 is
explicitly skipped pending a verified reward payer, recipient and receipt
chain/token.** The spUSDG vault receives retail deposits, so counting all
vault inflows as issuer income would materially overstate revenue. Set the
verified `receipt_sources` and remove `skip: true` to activate it. S63 position
tracking is active independently. This PR is a draft while these identities
and the Morpho/start-date conventions are being confirmed.

## Validation

Offline tests cover MSC isolation, legacy flags and snapshot decoding, API
inventory, the March spread switch, June Curve cutoff, unborrowed lending
eligibility, fee-net Morpho top-ups, negative prepaid balances, USDG receipt
basis and NFT ownership changes. Provider failures propagate; they are never
replaced with a zero accrual.

Live archive probes on 2026-10-25 pins verified the supplied pool IDs, the
RLUSD SparkLend reserve, Morpho's RLUSD asset, 10% performance fee, zero
management fee, and fee-adjusted redemption quotes. Official rate source:
[FRED DFEDTARL](https://fred.stlouisfed.org/series/DFEDTARL).
Fee accounting reference:
[Morpho Vaults V2](https://docs.morpho.org/developers/contracts/morpho-vaults-v2/).
These probes do not constitute a full historical accrual reconciliation.
