# PR #282 review and fixes

## Round 1 — reviewed head 6e3459c

- **P1:** The gate compared debt and deduction inputs but ignored the saved
  `utilized` borrowing principal. A stale principal could therefore pass with
  correct holdings. The gate now compares it with independently observed debt
  minus all seven deductions. Legitimate negative principal remains valid;
  the existing charging formula continues to clamp it when calculating fees.
- **P2:** `int(raw, 16)` accepted separators inside a 32-byte provider response.
  Archive balances now require exactly 64 hexadecimal digits after `0x`.
- **P2:** The per-account cent allowance could accumulate into a larger
  unsupported aggregate deduction. The aggregate now has its own cent limit.
- **P1 (validation):** The persisted-revision integration test failed because
  it expected canonical output without the newly required control evidence.
  It now exercises actual missing-proof rejection before isolating its
  database/revision/rendering assertions. No production approval is fabricated.

Regression reproductions failed against the original code for stale principal,
separator-containing archive output and accumulated rounding. After the fixes,
81 controls/monthly unit tests passed, including legitimate negative principal.

## Round 2 — reviewed first-round fix 79757bf

- **P2:** Missing zero-valued daily financial fields silently inherited zero.
  All seven deductions, debt and utilized principal must now be explicit.
- **P1:** Before ALM activation, a direct USDS wallet could allocate its value
  to a PSM exemption while reporting zero ALM idle. A raw-USDS wallet now allows
  only the ALM exemption; ownership and activation-date checks remain mandatory.
- **P2:** Decimal precision/traps inherited from a caller could reject valid
  evidence or change control arithmetic. Control and bridge checks now use an
  isolated precision context and preserve the caller's context unchanged.
- **P2:** Strictly positive/increasing pins excluded a chain's activation month
  and halted-chain closes. Zero pins now require retained, linked genesis and
  first-block evidence proving absence for that UTC day, with zero holdings.
  A genesis proof cannot serve as a live position read. Decreasing pins still
  fail; native-USDS wallet closes retain their UTC successor checks.
- **P2 (validation):** The first-round integration test left a temporary repo
  root active during workbook rendering. Its missing-proof assertion now scopes
  that override, then exercises the real renderer from the original repo root.

The first three regressions failed against 79757bf. New tests also cover valid
chain activation, missing/wrong/live/unlinked genesis proofs and attempts to
reuse a genesis proof for a live balance. RPC quantities/hashes now use strict
hex parsing. The capture CLI can retain genesis evidence and rejects aliased
output paths. No real passing production review or monthly replay was created.

Final focused verification: 167 unit tests passed; Ruff and diff checks passed.
PostgreSQL integration and complete-checkout CI results are recorded in the PR
body after the checks complete. The PR remains unmerged.
