# PR #215 — Borrowing costs per allocation for Sky-funded capital

## Deliverable

Calculate monthly borrowing costs per allocation for **Sky-funded principal**,
then combine those costs with existing venue revenue to report gross/net
returns and APYs through the monthly settlement API.

Principal is assumed Sky-funded except Spark Savings funding. Retained and
reinvested gains never become borrowed principal. Where a Savings mixture is
unresolved, publish the known capital/gross yield but leave the complete
borrowing cost and net yield null, with a reason. This PR does not calculate
the financing cost of Savings or other non-Sky liabilities.

## Included in the current scope

- Measure daily capital using existing movements/checkpoints. Retain the
  bookkeeping needed for deposits, withdrawals, reallocation, gains, losses,
  bridges and pending redemption claims.
- Apply existing borrowing rates and deductions to usable Sky-funded capital.
  Idle non-USDS stables are not exempt. Respect SDE/idle-USDS policy dates and
  keep any excess exemption separate for reconciliation.
- Reuse already calculated revenue. Keep the distinction between monthly
  returns and annualized yields, and between principal and the yield denominator.
- Publish versioned **monthly** allocation analytics, with explicit missing
  values and a drill-down by venue. The current reviewed dataset is August
  2026 for Spark/Grove; its capital timelines cover January-August.
- Preserve canonical global debt, borrowing costs, settlement amounts and
  daily API revenue. No published month is regenerated by this work.

## Deferred to the next PRD

Proving each deposit's ultimate minting origin, resolving the daily Sky/Savings
mix, Savings refinancing/VSR attribution, and certifying the complete global
funding reconciliation are not acceptance conditions for this PR. They belong
to [PRD_allocation_funding_next_steps.md](PRD_allocation_funding_next_steps.md).

Existing source-tracing work is retained because it produced reusable capital
normalization, authenticated receipts and opening checkpoints. The PRD has an
explicit code/reference inventory. Retention is not a claim that every earlier
investigation is part of this delivery. Paths are preserved so existing tests,
receipt fixtures, source hashes and reproduction commands remain usable.

## Routine pipeline boundary

Ordinary daily workers, the settlement CLI and historical monthly runner scripts
do **not** enable the old full funding-origin replay by default. It remains
available through explicit diagnostic runners or
`compute_monthly_pnl(..., include_allocation_financing=True)` for future research
and its existing tests. The monthly API reads stored results and never performs
that replay on request.

The older `allocation_financing` implementation is retained for that explicit
research path and for the shared annualization helper. It is not the acceptance
gate for the current assumption-based monthly dataset. Routine revenue
calculation and monthly allocation publication are separate steps.

## Acceptance

Known Sky-funded allocations have reproducible monthly costs and yields;
unresolved Savings mixtures remain explicit, not silently charged as all-Sky.
Known costs do not require a revenue row, but unknown revenue is never replaced
by zero to invent PnL. Missing or rounded values cannot masquerade as exemptions.
The API preserves precision, revisions and nulls, while published settlement
figures remain unchanged. Further origin research is a separate workstream.
